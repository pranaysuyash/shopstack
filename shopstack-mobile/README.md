# shopstack-mobile

React Native (Expo) mobile app for **ShopStack** — the voice-first kitchen inventory and shopping assistant.

Consumes the `shopstack` backend's `/api/v1` HTTP surface. The backend is a native Python FastAPI web app; this mobile client talks to it exclusively via the versioned API contract.

## Architecture

```
shopstack-mobile/
├── app/                        # expo-router file-based navigation
│   ├── _layout.tsx             # Root: auth gate + React Query provider
│   ├── (auth)/                 # Auth flow (login, register)
│   ├── (tabs)/                 # Main tabs (Today, Pantry, Shopping, Search, More)
│   ├── intelligence.tsx        # Recurring plan + meal plan
│   ├── account.tsx             # Privacy, retention, undo, server info
│   ├── traces.tsx              # Command history
│   ├── corrections.tsx         # Corrections list + create
│   └── store-mode.tsx          # Check off items while shopping
└── src/
    ├── api/
    │   ├── types.ts            # TypeScript interfaces mapping Python Pydantic schemas
    │   ├── client.ts           # HTTP client with Bearer token injection, caching, timeout
    │   ├── auth.ts             # Register, login, refresh, logout, whoami
    │   ├── inventory.ts        # List, add, consume inventory lots
    │   ├── shopping.ts         # Active list, create, complete, mark purchased
    │   ├── dashboard.ts        # Today snapshot
    │   ├── search.ts           # Global + inventory search
    │   ├── intelligence.ts     # Recurring plan, meal plan, decision explain
    │   ├── account.ts          # Purge, retention, undo, store mode toggle
    │   ├── traces.ts           # Trace list, detail, export
    │   └── corrections.ts      # List + create corrections
    └── storage/
        └── token.ts            # expo-secure-store wrapper (token, device id, API URL)
```

### Key design decisions

| Decision | Choice | Rationale |
|---|---|---|
| Framework | **Expo (managed)** | CRUD HTTP client — no native modules needed. EAS for OTA updates. |
| Navigation | **expo-router** (file-based) | Zero boilerplate, deep links built-in. |
| State / Cache | **TanStack React Query** | Stale-while-revalidate, automatic background refetch, offline resilience. |
| Auth | **Opaque bearer tokens** (device-level) | Stored in `expo-secure-store` (hardware-backed on iOS/Android). No password flow in v1. |
| API client | **Custom fetch wrapper** | Bearer token injection, 15s timeout, error categorization, in-memory caching. |
| Screens | **12 screens, full API coverage** | Every `/api/v1` router mapped to a screen or screen section. |

### Auth flow

1. **First launch:** User enters server URL → "Register New Device" generates a random `device_id` + `device_secret` → calls `POST /api/v1/auth/register` → stores token in secure store.
2. **Subsequent launches:** Root `_layout.tsx` checks for stored token → if found, shows tabs. Token is cached in memory and injected into every API call.
3. **Re-login:** If token is expired/revoked, login screen reads stored device credentials and tries `POST /api/v1/auth/login` automatically.
4. **Logout:** Clears token and device credentials from secure store → forces re-auth.

### API contract

All endpoints are under `/api/v1/*` and documented via OpenAPI (generated by the Python backend). The TypeScript types in `src/api/types.ts` are hand-mapped from `shopstack/api/v1/schemas/__init__.py`. Contract tests on both sides assert equality.

## Setup

### Prerequisites

- **Node.js** >= 18
- **npm** >= 9
- **Expo CLI** (`npx expo`)
- A running **shopstack** backend instance (default: `http://localhost:7860`)

### Quick start

```bash
cd shopstack-mobile
npm install
npx expo start
```

This starts the Expo Metro bundler. Scan the QR code with **Expo Go** (iOS/Android) or press `w` to open in the web browser.

### Configuration

The default server URL is `http://localhost:7860`. Change it on the login screen before connecting. The URL is persisted in secure storage.

## Screens

| Tab | Screen | API endpoints used | Features |
|---|---|---|---|
| **Today** | Dashboard | `GET /api/v1/dashboard/today` | Pantry count, use-soon, low items, recent purchases |
| **Pantry** | Inventory | `GET/POST /api/v1/inventory/lots`, `POST .../consume` | List, add, consume lots |
| **Shopping** | Shopping | `GET /api/v1/shopping/active`, `POST /api/v1/shopping/lists`, `POST .../complete` | Active list, create, complete → inventory |
| **Search** | Search | `GET /api/v1/search/inventory` | Semantic + text search, quick buttons |
| **More** | Settings Hub | Various | Links to Intelligence, Account, Traces, Corrections, Store Mode |
| — | Intelligence | `GET /api/v1/intelligence/recurring`, `.../mealplan` | Recurring plan + meal plan (tabbed) |
| — | Account | `GET /api/v1/account/privacy/retention-summary`, `.../undo`, `.../purge` | Server info, retention, undo, purge |
| — | Traces | `GET /api/v1/traces` | Command history list |
| — | Corrections | `GET/POST /api/v1/corrections` | List + create corrections |
| — | Store Mode | `GET /api/v1/shopping/active`, `POST /api/v1/account/store-mode/toggle` | Check-off items while shopping with progress bar |

## Development

```bash
# TypeScript check
npx tsc --noEmit

# TypeScript check (watch mode)
npx tsc --noEmit --watch

# Start Expo dev server
npx expo start

# Web build
npx expo export --platform web
```

### Adding an endpoint

1. Add the request/response types to `src/api/types.ts`.
2. Add the API function to the appropriate `src/api/<resource>.ts` module.
3. Wire it up in the screen component via `useQuery` / `useMutation`.
